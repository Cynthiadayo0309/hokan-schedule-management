# 訪問スケジュール管理

Windows 10 / 11向けの、インターネット接続を必要としない訪問スケジュール管理アプリです。Vue 3・TypeScript・Vite・Tauri 2・SQLite・ExcelJSを使用しています。

## 起動

ビルド済みのアプリは `配布/訪問スケジュール管理.exe` をダブルクリックしてください。インストールする場合は、同じフォルダー内の `-setup.exe` を実行してください。

Microsoft Edge WebView2 Runtimeが必要です。このPCには既存のWebView2を利用します。インストーラーにWebView2のダウンロード処理は含めていないため、別PCで未導入の場合は、事前にMicrosoft公式のオフラインインストーラーで導入してください。

初回は空の状態で起動します。「施設を登録」から開始するか、「サンプルで試す」で架空のデータを追加できます。参考写真の個人情報は初期データに含めていません。

## 基本の使い方

1. 施設を登録し、日勤ルート数（2 / 3）と訪問種類の色を設定します。
2. 利用者と職員を登録します。IDは施設内で重複できません。別施設は独立したデータです。
3. 定期訪問を登録します。毎週・週複数回・隔週・第1〜第5の曜日・単発に対応します。曜日ごとに時刻が異なる場合や1日複数回の訪問は、設定を分けて登録してください。
4. 「基本担当職員」で曜日・ルート別の職員を選択します。複数名を選択できます。
5. 週間画面で対象週を指定し、「スケジュール生成」→プレビュー確認→「下書き保存」と進めます。週を開くだけでは生成しません。
6. 日付をクリックすると日別詳細に移動します。予定の追加・編集・削除・担当職員変更・ルート入れ替えができます。予定はドラッグでも移動できます。クリックで開く編集フォームにも同じルート変更があります。
7. 内容を確認して確定します。確定時点の訪問予定、担当職員名、施設名、色、ルート数を保存します。確定後の変更も履歴に残ります。
8. 週間表・日別表をExcel出力、またはWindowsの印刷プレビューから印刷できます。下書きも出力可能です。

## 定期訪問と差分

- 隔週は「基準日が属する日曜始まりの週」を基準に、2週間おきに判定します。
- 第○週は、月内の第何回目の指定曜日かを判定します。第5の曜日がない月は生成しません。
- 「この日以降の定期予定も変更」は元のルールを前日までで区切り、新しいルールを追加します。過去のルールと生成済みの別週は保持します。
- 定期訪問を変更した後は「差分を確認」で追加・変更・削除候補・手動編集との競合を選んで反映します。
- 手動編集・削除との競合は初期状態では選択されません。選択した場合も置き換えの確認が入ります。
- 基本担当職員の変更は新規生成時に使います。生成済み週の担当変更は日別詳細から行います。
- 確定版は「変更履歴・確定版」から開き、その時点の内容を再出力・再印刷できます。

## 夜勤と重複

- 業務日と実際の訪問日時を別々に保存します。
- 月曜日の夜勤で火曜日0:30に訪問する場合、業務日を月曜日、開始時刻を `24:30` にしてください。`25:15` は翌日1:15です。夜勤は `47:59` まで、所要時間は1〜1440分で登録できます。
- `00:30` と入力した予定を、自動的に前日の夜勤に移動することはありません。
- 同じ開始時刻の予定が複数あっても、行を増やして表示・Excel出力します。日勤と同時刻の夜勤は別の行で日勤列を横断します。
- 重複は開始時刻と所要時間で判定します。同じルート・利用者・担当職員の重複、職員の不足などを警告します。前後の週との跨日重複も確認します。警告を確認して保存できます。
- 日勤Cに予定や職員が残っている間は2ルートへ変更できません。先に移動してください。

## 保存・バックアップ

Windows版は `%APPDATA%/jp.local.visit-schedule/schedule.sqlite3` にSQLite形式で保存します。全施設のデータを1つの状態としてSQLiteのトランザクションで保存し、更新番号により複数ウィンドウ間の上書きを防ぎます。保存に失敗した場合、画面上の確定データも入れ替えません。

「施設・設定」から全施設のJSONバックアップを出力できます。取り込み時は形式と参照関係を検証し、内容のプレビュー後に次のどちらかを選びます。

- **別施設として追加**：IDを新しくし、現在の施設を保持します。
- **全施設を復元**：バックアップの内容で全施設を置き換えます。現在のデータを先にバックアップしてください。

ブラウザから起動する開発確認モードではブラウザのローカルストレージを使います。Windows版のSQLiteとは別の保存領域です。本番利用はWindows版を使用してください。

データベース、バックアップ、Excelは暗号化されません。Windowsアカウントと保存フォルダーを適切に管理してください。定期的にアプリ内のバックアップを取り、アクセスが制限された場所に保存してください。SQLiteを直接コピーする場合はアプリを終了してください。WALファイルがある状態で本体だけをコピーすると、最新の保存内容を含まない場合があります。

## 開発・確認

Node.js 22.12以降、RustのMSVCツールチェーン、Visual StudioのC++ビルドツール、WebView2が必要です。

```powershell
npm ci
npm test
npm run build
npm run desktop
npm run desktop:build
```

テストは頻度判定、隔週、月末、跨日夜勤、重複、定期ルールの分割、手動編集との競合、複数職員の入れ替え、確定版、施設コピー、バックアップ検証、週間・日別Excelの欠落確認を対象にしています。

Tauri公式資料：[Windowsの開発環境](https://v2.tauri.app/start/prerequisites/)、[Windowsインストーラー](https://v2.tauri.app/distribute/windows-installer/)。

## 範囲と制限

- 提供された実装指示はExcel出力の段落途中で終わっています。そこまでに記載されている要件と参考画像2枚を基に実装しています。
- 週単位のルート一括交換、自動ルート最適化、クラウド同期は実装していません。日別の交換と手動ファイル共有に対応します。
- 写真の用紙をそのまま複写するのではなく、日曜始まり・共通時間軸・日勤列・横断する夜勤・種類別の色を再現しています。印刷の用紙サイズ・倍率・背景色はプレビューで確認してください。
- 印刷の初期指定はA3横、Excelの日別出力はA4横です。大量の行は複数ページになります。
- 既存のExcel一覧からの自動取り込みや画像のOCR登録は含めていません。
- 電子署名と実機プリンターでの出力確認は未実施です。
